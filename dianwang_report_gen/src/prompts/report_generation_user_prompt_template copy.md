## 任务
你的任务是根据提供`输入内容`的原始文本信息，生成一份结构完整、逻辑清晰的工程可研报告。

## 任务细节

### 内容
- 尽可能地保留`输入内容`的文本信息：将输入中的内容整理后按照报告模板的要求保留在报告中，尽量不进行任何修改或解释。
- 叙述连贯性：报告内容必须使用流畅、专业的中文工程语言，保持各部分之间的逻辑连贯。
- 洞察整合：洞察是对输入内容的分析和总结，需要根据洞察组织语言然后在报告中进行展示。
- 大纲中的每一个项目分点对应生成一个或多个段落，避免使用分点直接展示。
- 如果地点之间用波浪号`~`连接，在输出时添加转义符`\~`，避免与Markdown的链接语法冲突。
- 只需要根据输入的内容进行分析，不需要自己生成数据。即使大纲模板中要求展示某些内容的数据，也只需要根据输入的内容进行展示。

### 表格
- 在需要展示表格的地方，使用下面提供的`Pandoc表格语法`组织表格数据，确保表格的可读性和专业性。
- 避免在表格所有行前面添加缩进，让表格从行首开始生成。
- 为了让结构更清晰，在列表项和表格之间添加一个空行。

### 可视化
- 占位符：在需要展示图的地方，加入一个“可视化占位符”`<visualization></visualization>`。每个可视化占位符还应建议一个该图表所支持或解释的叙事元素。
- 标签中应该包含全部数据：可视化占位符中的标签应包含图表所需的所有数据，避免在标签中使用占位符或自己生成数据。
- 信息：可视化占位符必须包含有关该图表的必要信息，例如：
    - 图表标题（英文）
    - 图表类型
    - x轴和y轴标签（中文）
    - x轴和y轴的数据值等。
- 标签：可视化图表必须位于一对 `<visualization></visualization>` 标签之间。

## 引用
如果输入数据中包含引用，则必须在生成的内容中使用引用包围引用的raw_value内容。
请使用细粒度的引用，如具体的数值、指标、数据项等。
引用的格式如下：
[cite_start]<raw_value>[cite_source: <source>]
如果发现引用错误，请及时修正。
