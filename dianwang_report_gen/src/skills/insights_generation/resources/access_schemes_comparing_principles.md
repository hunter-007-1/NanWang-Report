## 接入方案分层比选体系

接入系统方案比选采用“安全硬约束准入 → 安全可行方案技术性能比较 → 全寿命经济性与工程实施比较”的顺序。核心汇总表是当前方案级结果的最高优先级来源；明细表只用于解释具体问题场景，不得推翻汇总结果。

### 阶段一：安全硬约束准入

先检查输入已经提供的基态潮流、N-1、短路开断能力、故障后设备负载、电压和暂态稳定结果。任一明确硬约束失败的方案不得进入最终推荐集合；缺少关键安全数据的方案应标记为“安全性尚未证明”，不得默认通过。

N-1通过率仍按现有区间解释：100%为最优，大于95%且小于100%为较优，90%至95%为可用但需关注，低于90%为运行适应性较弱。该区间只解释N-1表现，不覆盖短路、过载、电压或暂态硬约束。

若输入只有 `total_contingencies_run` 和 `contingencies_with_issues`，可按 `(total_contingencies_run - len(contingencies_with_issues)) / total_contingencies_run * 100%` 计算；汇总表已有结果时直接引用，不重新估算。

### 阶段二：技术性能比较

只在安全可行方案之间比较电压、负载、网损、关键断面、N-1表现和暂态稳定等已有技术指标。所有判断方向和阈值沿用 `compare_rules`，不新增综合评分、权重或指标。

若全部方案安全失败，可以展示相对表现用于定位整改方向，但必须明确这些相对优势不构成最终推荐。缺失项统一写“当前输入不足，未评价”；问题明细子集不得冒充全网最大值、合格率或越限率。

### 阶段三：全寿命经济性与工程实施比较

正式经济择优只面向安全可行方案。比较输入中已有的建设投资、运维成本、年费用、LCC、线路长度和工程条件；不补造现金流，不改变 LCC 状态，不对不一致的长度单位进行横向排序。

若全部方案安全失败，仍可列出经济排序，但第一名只能称为“整改优先候选方案”，并说明其必须完成整改和重新仿真校核后才具备进一步比选资格。

### 综合推荐逻辑

1. 先给出安全硬约束通过、失败或未证明状态及依据。
2. 再对安全可行方案比较技术性能；全部失败时只说明整改方向。
3. 最后比较安全可行方案的全寿命经济性和工程实施性。
4. 只有安全可行方案可以称为最终推荐方案。全部失败时结论必须是“当前没有可直接推荐实施的方案；所有方案需整改后重新仿真校核”。
5. 所有结论必须可追溯到输入；没有数据的项目不评价。
