# 一、当前系统报告生成现状

## 1.1 当前技术路线

经 AI_CONTEXT 导航并回查源码，当前主流程由 LangGraph 串联：

```text
输入 JSON/仿真结果
  → data_preprocessing_pcn（清洗、指标派生、Markdown 数据表）
  → insights_generation_node（LLM/Agent 生成比选洞察）
  → retrieve_claims_for_insights（检索可追溯事实）
  → generate_report（单次长文生成、可选图表代码生成、二次润色）
  → verify_pcn_claims（Claim/Calculate 校验）
  → convert_report（Pandoc 输出 DOCX；XeLaTeX 输出 PDF）
```

关键实现证据：

- `src/workflow.py:43-65` 定义了预处理、洞察、事实检索、报告生成、校验和转换节点。
- `src/nodes/generate_report.py:325-354` 将数据表、洞察、背景与 Claim 一次性送入模型生成长文。
- `src/nodes/generate_report.py:366-519` 仅当模型主动输出 `<visualization>` 时，再让模型生成 Matplotlib 代码并执行、插图。
- `src/nodes/generate_report.py:533-545` 对整篇报告再次调用模型润色，之后才执行安全结论修正。
- `src/nodes/convert_report.py:612-680` 使用 Pandoc 直接生成 DOCX，使用 Pandoc + XeLaTeX 生成 PDF；当前未传入 Word `reference-doc`，也没有项目级 HTML/CSS 或完整 LaTeX 视觉模板。

因此，当前系统是“指标与事实较结构化，报告组织与图表较依赖 LLM，输出端只有基础格式参数”的路线。

## 1.2 已有能力

- 指标派生、缺失值状态、方案级 Claim 和 Calculate 溯源已具备较好基础。
- 已能输出 Markdown、DOCX、PDF，并保留用户编辑稿和版本。
- 安全结论已有程序化兜底，能够阻止安全不合格方案被直接作为最终推荐。
- 当前数据预处理已能生成安全硬约束、技术性能、经济性三张核心汇总表。

# 二、行业最佳实践调研

## 2.1 内容生成：从一次性长文改为“规划—事实—分节写作—验证”

长报告生成领域的共同趋势不是扩大单次提示词，而是增加中间结构和证据约束：

- [MM-PAW（INLG 2024）](https://aclanthology.org/2024.inlg-main.52/)先生成包含文本与图片意图的中间计划，再按章节写作；论文报告其在相关性、结构和依据性方面优于直接生成。
- [EviReport（ACL Findings 2026）](https://aclanthology.org/2026.findings-acl.1397/)指出一次性长文容易漏事实、漂移数字和遗漏关键视觉证据，采用“可追踪证据单元—粗到细大纲—事实优先迭代写作—缺口补齐”，并同时评估事实正确性、覆盖率和视觉证据。
- [Deep-Reporter（ACL 2026）](https://aclanthology.org/2026.acl-long.1909/)采用清单驱动的增量合成和循环上下文管理，解决长文局部流畅但全局失序的问题。
- [ToTTo（EMNLP 2020）](https://aclanthology.org/2020.emnlp-main.89/)表明，即使生成文本很流畅，也可能出现表格不支持的描述。工程上应先由规则选定单元格/事实，再让模型负责表述。
- [ReportGPT（EMNLP Industry 2024）](https://aclanthology.org/2024.emnlp-industry.39/)将表格到报告拆成领域脚本生成、脚本执行、表层语言生成和人工反馈，使数值分析先执行、后表达，适合本项目的 Claim/Calculate 路线。
- [WriteHERE（EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.1254/)及其[开源代码](https://github.com/principia-ai/WriteHERE)采用递归任务分解，把检索、推理和写作拆开，适合中期的分章节证据包生成。
- [Retrieve-Plan-Generation（EMNLP 2024）](https://aclanthology.org/2024.emnlp-main.270/)采用迭代检索与规划，说明长文应在写作过程中检查证据缺口，而不是只在开头检索一次。
- [Variational Sequential Planning（TACL 2022）](https://aclanthology.org/2022.tacl-1.40/)把内容规划与文本生成交替进行，为后续“章节计划—章节写作—覆盖率检查”提供了可借鉴路线。
- [SAFE 长文本事实性评估代码](https://github.com/google-deepmind/long-form-factuality)将长回答拆成可核验事实并逐项验证；本项目不照搬联网搜索，但可借鉴其“原子事实—证据—通过/失败”质量门禁。

对本项目的直接启示：报告大纲、安全准入、数值、排序、表格和图表选择应由规则控制；LLM只在每个章节的“许可事实包”内完成解释、过渡和专业化表达。

## 2.2 排版：内容模型与输出格式解耦

成熟报告系统通常先形成独立于格式的文档模型，再分别渲染 PDF、Word、HTML：

- [Pandoc 用户手册](https://pandoc.org/MANUAL.pdf)支持使用 `--reference-doc` 控制 DOCX 样式；本项目已经依赖 Pandoc，加入企业 Word 模板是最低成本改进。
- [Quarto](https://github.com/quarto-dev/quarto-cli)构建在 Pandoc 之上，提供图表/表格/公式/章节交叉引用、项目级配置和多格式输出；[交叉引用文档](https://quarto.org/docs/authoring/cross-references)可自动维护图表编号和链接。
- [WeasyPrint](https://weasyprint.org/)把 HTML/CSS/SVG 转为打印级 PDF，支持分页、页边距、页眉页脚和多页布局，且为 Python 工具，适合中期引入 PDF 预览与主题系统。
- [python-docx-template](https://docxtpl.readthedocs.io/en/stable/)允许在现有 Word 模板中使用 Jinja2 数据，适合严格复刻固定企业模板，但复杂循环表格与富文本维护成本高于 Pandoc `reference-doc`。
- [Typst](https://github.com/typst/typst)是现代排版系统，支持页眉页脚、自动分页和可重复跨页表头；[官方表格说明](https://typst.app/docs/guides/tables/)明确支持长表跨页及重复表头。它可作为长期 PDF 引擎候选，但近期迁移收益不足以抵消新工具链成本。
- [JasperReports](https://github.com/Jaspersoft/jasperreports)支持像素级模板、多数据源和多格式输出，适合传统企业报表；但 Java/JRXML 技术栈与当前 Python 项目差异大，不宜作为本项目近期主方案。

## 2.3 图表：从“模型写任意代码”改为“语义意图—受控规格—确定性渲染”

- [LIDA](https://github.com/microsoft/lida)把图表生成拆成数据摘要、可视化目标、代码生成/执行/筛选和信息图模块，说明图表不应由一次自由文本决定。
- [Data Formulator](https://github.com/microsoft/data-formulator)强调将数据变换与图表配置分离，并保留可检查的数据血缘；这比让模型直接写整段绘图代码更容易校验。
- [LIDA 论文](https://arxiv.org/abs/2303.02927)进一步把图表生成定义为多阶段任务，而非单次代码生成。

对本项目的直接启示：建立固定图表注册表，模型最多选择“叙事意图”，数据字段、单位、阈值、颜色、排序和渲染代码由程序确定。

# 三、开源项目分析

| 项目/方案 | 定位与架构 | 优点 | 局限 | 本项目适配结论 |
|---|---|---|---|---|
| Pandoc + reference.docx/LaTeX template | Markdown AST 到多格式 | 已在项目中；改造最小；Word 可编辑 | 复杂卡片式布局和 PDF 视觉调试较弱 | **近期首选** |
| Quarto | Pandoc 上层技术出版系统 | 目录、编号、交叉引用、项目主题成熟 | 增加 CLI 和配置层；不是内容质量方案 | 中期可选，不必立即引入 |
| HTML/CSS + WeasyPrint | Jinja2/HTML + CSS Paged Media → PDF | 视觉可控、浏览器式开发、Python 集成自然 | DOCX 仍需独立通道；部分现代 CSS 支持有限 | **中期 PDF 首选** |
| docxtpl | DOCX 模板 + Jinja2 数据 | 严格保持甲方 Word 模板、页眉页脚和固定版式 | 动态长章节、复杂富文本、跨页表格维护较繁琐 | 有固定官方模板时采用 |
| LaTeX/XeLaTeX | 文本/模板 → 高质量 PDF | 数学、目录、长表和交叉引用成熟 | 中文字体、宏包和 Windows 环境维护较重 | 保留现有通道并模板化 |
| Typst | 现代标记语言 → PDF | 编译快、错误清晰、分页与长表能力好 | 新语法和生态迁移成本 | 长期备选，不作为 P0 |
| JasperReports | 数据源 + JRXML 模板 → 多格式 | 企业级、像素级、报表服务器生态 | Java 重栈、模板开发成本高 | 不建议迁入当前系统 |
| LIDA/Data Formulator | AI 辅助图表意图、数据变换、可视化规格 | 分阶段、可检查、图表丰富 | 面向探索分析，不直接满足电网规则 | 借鉴架构，不整体嵌入 |

# 四、论文研究方向分析

## 4.1 可直接落地的研究思想

| 研究方向 | 核心思想 | 在本项目中的应用 |
|---|---|---|
| Plan-and-Write | 先规划章节和图文证据，再写正文 | 新增规则化 `ReportPlan`，逐节生成，不再一次生成全文 |
| Evidence-first generation | 先抽取/绑定事实，再组织语言 | 每节携带允许使用的 Claim、Calculate、表格行和缺失项 |
| Controlled table-to-text | 仅描述规则选择的表格单元格 | 先计算最优/最差/阈值偏差，再让 AI 解释原因 |
| Checklist-guided synthesis | 用章节清单检查覆盖率 | 必选章节、必选表、必选图、必写结论均可自动验收 |
| Multimodal report generation | 文本和视觉证据协同规划 | `ChartSpec` 与章节计划绑定，图先生成、文再引用 |
| Visualization grammar | 用声明式规格代替自由代码 | 图表注册表 + 严格字段映射 + 固定主题与阈值线 |

## 4.2 不建议直接照搬的部分

本项目的数据已由本地仿真和指标模块产生，不需要引入大规模联网检索、多 Agent 网页搜索或图像检索。论文中的“证据包、大纲、分节写作、覆盖率评估”值得采用；其大规模检索基础设施不属于当前主要矛盾。

# 五、当前系统问题分析

## 5.1 P0：业务规则和报告大纲互相冲突

优化前，报告技能要求安全硬约束优先，但旧版报告大纲仍要求以经济排序为主要依据并输出具体推荐方案。后处理再追加安全结论，容易出现“前文推荐、末尾否决”和结论重复。本次已统一两处规则；该项从现存缺陷转为回归检查项。

这是当前最先要修复的问题，优先级高于换渲染器或换模型。

## 5.2 内容与信息组织问题

- 报告正文和章节顺序主要由一次长文本生成决定，没有机器可校验的章节计划。
- 数据预处理已生成三张核心汇总表，但最终正文是否完整采用仍由模型决定，存在信息丢失。
- 缺少一页式执行摘要、数据质量摘要、整改优先事项和结论状态卡。
- 多处明细直接堆入正文，核心比较与附录明细没有分层。
- 二次全篇润色可能改变公式、数字标签、标题和结构，增加新错误面。

## 5.3 图表问题

- 图表触发权交给 LLM；当前样例 0 张图，说明链路不具备确定产出能力。
- 图表代码也由 LLM临时生成，字段、单位、阈值和排序难以统一验证。
- 缺少图表目录、编号、题注、数据来源、阈值线、色盲/灰度兼容规范。
- 雷达图和趋势图若数据不完整或只有单场景，容易制造误导。

## 5.4 排版与工程规范问题

- DOCX 没有 `reference-doc`，标题、正文、表格、题注、目录、页眉页脚缺少统一企业样式。
- PDF 只有字体和文档类参数，未形成封面、目录、章节起页、横向长表、图表题注等完整模板。
- Markdown 管道表对超宽表格和跨页表头控制有限。
- 没有输出后逐页渲染检查，可能遗漏溢出、断行、孤立标题和表格截断。
- 缺少版本号、编制/校核/审核栏、数据基准日、模型/规则版本和“未评价项”附录。

## 5.5 AI 内容质量与质量门禁问题

- 47/47 Claim 通过说明事实绑定有效，但 5/6 Calculate 失败表明 AI 仍在手工拼接来源与公式。
- 样例存在方案4、方案5复用方案3 Claim 的现象；数值相同不代表来源正确，当前校验更偏“值是否匹配”，还需“方案归属是否匹配”。
- `ready=true` 只是草稿可打开，不等于可交付；企业级系统应明确 `DRAFT`、`REVIEW_REQUIRED`、`DELIVERABLE` 三种状态。

## 5.6 与企业级可研报告的差距

企业级可研报告要求同时具备：稳定结构、可审计数据来源、统一专业术语、完整图表、正式版式、修订记录、人工签审位置和可重复生成。当前系统已具备“数据—文本—导出”的主链路，但尚缺“结构化文档模型、确定性视觉层、规则/AI边界、交付级质量门禁”四个中间层。

# 六、推荐优化方案

## 6.1 总体原则

采用“规则定事实和结论，AI写解释，模板定版式”的混合方案：

```text
现有输入与仿真结果
  → 现有指标计算 / derived_metrics
  → 决策引擎（安全硬约束、排序、缺失状态）
  → Report IR（统一报告数据模型）
  → 规则化 ReportPlan（章节、表、图、证据、缺失策略）
  → 分章节 LLM Writer（只使用章节证据包）
  → 事实/计算/结构/归属校验
  → 确定性图表渲染
  → Markdown/HTML/DOCX/PDF 渲染
  → 页面级视觉检查与交付门禁
```

## 6.2 三类方案比较与选择

### 方案 A：报告规划 Agent

保留，但不让 Agent 自由决定业务结构。由规则先产生必选章节和证据边界，AI只补充章节叙事目标和过渡语。适合提升信息组织和内容质量。

### 方案 B：Markdown → HTML/CSS → PDF

中期推荐。Markdown 继续作为可编辑中间稿，结构化模型通过 Jinja2 生成 HTML，WeasyPrint 生成 PDF。适合封面、摘要卡片、风险矩阵、页眉页脚和复杂图文混排。

### 方案 C：DOCX 模板引擎

作为 Word 输出通道保留。近期优先用 Pandoc `reference.docx`，只有拿到严格固定的官方 Word 母版且 Pandoc 无法复刻时，再切换该通道到 docxtpl。

### 推荐组合

不是三选一，而是“A 负责内容架构 + B 负责高质量 PDF + C 负责可编辑 Word”。三者共享同一 Report IR，避免为 PDF 和 Word分别生成两套正文。

## 6.3 新报告结构

1. 封面：项目名、报告类型、版本、日期、编制/校核/审核栏（规则/模板）。
2. 执行摘要：是否存在可实施方案、首要风险、整改优先候选、3—5项关键数字（规则生成，AI只润色解释）。
3. 项目概览与数据范围：单场景口径、输入完整度、未评价项（规则生成）。
4. 候选方案总览：接线方式、工程量、投资和关键差异（表格规则生成，AI概述）。
5. 比选原则与判定流程：安全硬约束 → 技术性能 → LCC → 辅助指标（规则生成）。
6. 安全校核：基态、N-1、短路、暂稳及问题清单（数值和判定规则生成，AI解释风险）。
7. 技术性能比较：电压、负载、网损、关键断面等（规则表图 + AI分析）。
8. 经济性与 LCC：成本构成、假设、缺失成本项和敏感性（规则计算，AI解释）。
9. 工程实施与规划衔接：施工、停电、远期适应性（有数据才评价）。
10. 风险矩阵与整改建议：风险、严重度、概率、措施、复核条件（规则为主，AI辅助措辞）。
11. 综合结论：可实施推荐或“无可直接推荐方案”；经济候选必须明确标注为整改基础（规则生成）。
12. 附录：指标定义、数据缺口、公式、Claim/Calculate审计、详细 N-1 与短路明细（规则生成）。

## 6.4 AI 与规则的边界

| 内容 | 生成责任 |
|---|---|
| 数值、单位、公式、阈值、缺失状态 | 规则 |
| 安全是否通过、方案是否允许推荐 | 规则 |
| 排名、最优/最差、阈值偏差 | 规则 |
| 表格、图表类型、字段、题注和编号 | 规则 |
| 背景综述、指标解释、差异原因、段落过渡 | AI，受证据包约束 |
| 风险措辞、整改建议初稿 | AI + 规则清单 + 人工确认 |
| 封面、目录、页眉页脚、样式 | 模板 |

# 七、技术架构设计

## 7.1 Report IR

建议使用 Pydantic 增加一个与输出格式无关的模型：

```text
ReportDocument
├─ metadata：项目、版本、日期、场景、规则版本
├─ decision：硬约束状态、可推荐状态、整改候选
├─ sections[]：章节计划、证据 ID、AI 模式、缺失策略
├─ tables[]：列定义、行、单位、阈值、来源
├─ charts[]：类型、指标键、系列、阈值、题注、来源
├─ risks[]：风险、等级、依据、措施、复核条件
└─ appendices[]：明细、公式、审计记录
```

`Report IR` 不替换 `derived_metrics.json`，而是消费它；现有指标模块无需重构。

## 7.2 图表增强方案

建立固定 `ChartRegistry`，输入 `ChartSpec` 后调用现有 Matplotlib 生成图，禁止执行模型临时写出的任意绘图代码。

| 图表 | 使用条件 | 表达目的 |
|---|---|---|
| 安全硬约束矩阵/热力图 | 总是生成 | 一眼显示各方案通过、失败、未评价 |
| 带阈值线的分组柱状图 | 至少2个方案且单位一致 | N-1、负载率、开断裕度、成本对比 |
| LCC成本构成图 | 完整成本分项存在 | 展示建设、运维、网损、停电等构成 |
| 风险矩阵 | 风险等级与概率有依据 | 展示优先整改项 |
| 方案优缺点卡片 | 总是可用 | 用结构化 HTML/Word 表格呈现，不作为统计图 |
| 网络拓扑图 | 有真实节点、支路、状态数据 | 展示新建、拆除和保留线路；使用 Graphviz/NetworkX 固定图例 |
| 雷达图 | 指标完整、已归一化、且不含硬约束 | 仅作技术性能辅助，不得代替安全判定 |
| 趋势图 | 有多时段/多场景数据 | 当前单场景数据不生成，避免伪趋势 |

图表流水线：`derived_metrics → ChartSpec 校验 → 单位/缺失检查 → 固定 renderer → PNG/SVG → 图表清单校验 → 插入章节并交叉引用`。

## 7.3 排版方案

### 近期：强化现有 Pandoc 路线

- 增加 `templates/reference.docx`：设置封面、标题1—4、正文、表格、题注、目录、页眉页脚和中文字体。
- 增加 `templates/report.tex` 或 header include：控制 A4、页边距、章节起页、长表、横向页面、题注和目录。
- Markdown 元数据统一提供项目名、版本、日期、编号、编制/校核/审核字段。
- 自动给表、图、公式生成稳定 ID、编号和题注；可直接采用 Pandoc 过滤器，或中期引入 Quarto。

### 中期：增加 HTML/CSS PDF 通道

- `Report IR → Jinja2 HTML → report.css → WeasyPrint PDF`。
- CSS 使用 `@page` 管理页眉页脚、页码与章节首页；长表重复表头，超宽表自动横向或拆表。
- HTML 同时作为浏览器预览，使网页看到的报告与 PDF 接近。
- DOCX 继续从同一 Report IR 生成，不让 PDF/Word 内容分叉。

### 长期：按真实需求评估 Typst/Quarto

若后续出现大量复杂公式、跨章节交叉引用和多册报告，可做 Typst/Quarto 概念验证；在现有模板方案未达到瓶颈前不迁移。

## 7.4 质量门禁

报告进入 `DELIVERABLE` 必须同时满足：

- 必选章节、核心表、必选图覆盖率 100%。
- Claim 通过率 100%，Calculate 通过率 100%，正文无 `!` 或待验证标签。
- 方案归属校验 100%，不得跨方案复用错误 Claim。
- 安全硬约束结论与推荐状态一致，安全不合格方案不得出现“最终推荐/建议实施”。
- 所有图表文件存在，字段、单位、阈值与来源校验通过。
- PDF 逐页转图片后无裁切、重叠、空白异常、孤立标题；长表表头重复。
- DOCX 样式、目录、题注、页眉页脚和分页抽检通过。

建议状态语义：

- `DRAFT_READY`：生成完成，可编辑。
- `DRAFT_REVIEW_REQUIRED`：有事实、计算、结构或视觉门禁失败。
- `DELIVERABLE`：所有自动门禁通过，仍保留人工签审流程。

# 九、本次已经实施的优化

本次改动严格限定在报告生成、提示词、结论保护、任务状态和测试层，没有修改指标公式、指标键、阈值、单位、`derived_metrics.json` 结构或三张核心汇总表的来源。

## 9.1 已落地的方法

1. **安全优先的规则化规划**：洞察和报告大纲统一为“安全硬约束准入 → 安全可行方案技术比较 → 安全可行方案经济与实施比较”。全部方案失败时只允许输出整改候选，不输出最终实施推荐。
2. **证据受控写作**：报告提示要求按章节分配既有数据、Claim、Calculate 和缺失项；禁止新增指标、权重、阈值或无依据数值。
3. **程序化核心表格**：三张核心汇总表从预处理阶段已有 Markdown 表格幂等插入，模型遗漏时自动补齐，源表缺失时记录缺项而不伪造。
4. **确定性核心图表**：从 `derived_metrics.json` 读取状态为 `ok` 的既有 N-1 通过率、最小开断裕度率和年费用，使用固定字段、单位、主题和判定线生成对比图。该过程只展示现有值，不重算指标。
5. **关闭自由绘图默认路径**：默认不再以停止标签触发“模型写绘图代码并在本机执行”；旧流程仅在显式设置 `REPORT_ENABLE_LLM_CHART_CODE=1` 时保留兼容。
6. **润色保护**：二次润色前把 Claim、Calculate、Markdown 表格和图片替换为不可编辑占位符；模型改坏或丢失占位符时直接放弃本次润色，保留原文。
7. **结构质量门禁**：自动检查九个必选章节、三张核心汇总表、图片数、Claim 数和 Calculate 数；检查结果写入 `report_quality_result`，与 PCN 校验共同决定 `DRAFT_READY` 或 `DRAFT_REVIEW_REQUIRED`。
8. **结论标题兼容**：安全结论后处理同时识别旧的“综合比较推荐方案”和新的“综合比较与结论”，避免重复添加结论章节。
